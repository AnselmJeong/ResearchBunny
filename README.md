# ResearchBunny

관심 논문에서 출발해 참고문헌과 후속 연구를 탐색하고, 선별한 논문을 로컬 아카이브로 보관하는 macOS 앱입니다. [PRD](PRD.md)의 P0 흐름을 구현한 **0.3.0 로컬 시험판**입니다.

화면과 함께 주요 작업 흐름을 따라가려면 [사용 가이드](Usage.md)를 참고하세요. 이미 정리한 PDF 폴더를 앱 전체의 서고로 쓰는 기능은 [0.3.0 릴리스 기록](docs/release-0.3.0.md)과 [서고 구현 기록](docs/shelf.md), 서고 수신함·수신함 정리·서고 위치 바꾸기는 [0.3.1 릴리스 기록](docs/release-0.3.1.md), 선택 바의 휴지통 버튼과 서고 목록의 휴지통 처리는 [0.3.2 릴리스 기록](docs/release-0.3.2.md), 수신함 정리 창이 지금 수신함을 보이게 한 수정, 영구 삭제 때 서고 PDF를 지우는 변경, 휴지통 문헌의 선택 정리는 [0.3.3 릴리스 기록](docs/release-0.3.3.md), 수신함과 미분류를 나누고 정리 창이 지난 제안 대신 지금 수신함으로 시작하게 한 변경, 최근 사용 순 프로젝트 목록과 프로젝트 이름 바꾸기·삭제, 아카이브에서 빼기와 모두 선택, 행 클릭 시 원문을 읽지 않는 목록, 내보낸 PDF의 서고 이름 유지는 [0.3.4 릴리스 기록](docs/release-0.3.4.md), 영구 삭제 때 서고 PDF를 남길지 지울지 고르는 선택은 [0.3.5 릴리스 기록](docs/release-0.3.5.md), 연구 질문을 영어 OpenAlex 검색어로 바꾸는 seed 검색어와 관련 논문 탐색의 400 오류 수정은 [0.3.6 릴리스 기록](docs/release-0.3.6.md), 앱이 내려받은 PDF를 몇 초 안에 임베딩하고 사이드바에 임베딩 진행을 보여 주는 변경은 [0.3.7 릴리스 기록](docs/release-0.3.7.md), 프로젝트 전환·생성 개선은 [0.2.10 릴리스 기록](docs/release-0.2.10.md), PDF reader와 AI 대화 기록은 [0.2.9 릴리스 기록](docs/release-0.2.9.md)에 정리했습니다.

## 설치와 실행

0.3.0은 Electrobun 1.18.1 + Bun 1.3.8 + macOS 기본 WebKit으로 실행합니다. Chromium/CEF를 포함하지 않습니다.

- 배포 DMG: `out/electrobun/stable-macos-arm64-ResearchBunny.dmg`
- 앱: `build/stable-macos-arm64/ResearchBunny.app`
- DMG의 앱을 Applications로 복사한 뒤 실행하세요. 첫 실행은 번들 압축을 풉니다.
- 로컬 ad-hoc 서명입니다. Developer ID 서명과 Apple 공증은 하지 않았습니다.
- macOS Apple Silicon에서 검증했습니다. Intel과 다른 OS는 이번 전환 범위에 포함하지 않습니다.
- Electron 버전은 종료하고 새 앱을 실행하세요. 기존 라이브러리 경로와 SQLite 형식은 유지합니다.
- 파일 드롭은 지원하지 않습니다. 가져오기 창에서 여러 PDF 또는 여러 폴더를 선택하세요.


## 첫 아카이브 만들기

1. 검색창에 키워드·제목·DOI·OpenAlex ID를 넣습니다. 기존 BibTeX 또는 PDF로 시작할 수도 있습니다.
2. 문헌 제목을 누르면 첨부 PDF가 있는 논문은 원문을 엽니다. 상단의 `탐색 / 원문`으로 목록과 PDF를 전환하며 오른쪽 `문헌` 탭에서 초록과 출처를 확인합니다. 체크박스는 일괄 작업용 선택입니다.
3. 선택한 논문을 `seed`로 지정하고 연구 질문을 저장합니다. 이 초기 관심 기준은 다음 탐색에서 다른 논문을 선택해도 바뀌지 않습니다.
4. `관련 논문`, `참고문헌`, `후속 인용`, `공통 참고문헌`, `공통 후속 연구` 중 필요한 탐색을 실행합니다. 선택 집합 또는 아카이브를 출발점으로 사용합니다.
5. 필터에서 관련성·연도·최소 인용수 등을 조절합니다. 숨겨진 후보와 초록 부족으로 판단을 보류한 후보도 확인할 수 있습니다.
6. 목록·그래프·연도 보기에서 문헌을 선택해 저장하고, 컬렉션·별표·태그·읽기 상태·노트를 정리합니다.
7. 내보내기 창에서 선택·컬렉션·프로젝트·전체 범위와 편수를 확인하고 BibTeX를 저장합니다. 비공개 노트와 파일 경로는 기본 출력에서 제외합니다.

상단의 **뒤로/앞으로** 버튼은 당시 선택·필터·보기 상태를 복원합니다. 결과 위의 **탐색 경로**에서 원하는 부모 단계를 바로 누를 수도 있습니다. 예를 들어 3편을 선택해 관련 논문을 탐색한 뒤 검색 단계로 돌아오면, 같은 3편으로 후속 인용을 찾을 수 있습니다. 탐색을 이어 가다 마음에 들지 않으면 뒤로 버튼으로 필요한 단계까지 되돌아가 다시 갈라지면 됩니다. 새 키워드 검색은 독립된 경로로 시작합니다.

0.1.2에서는 **관련 문헌 찾기** 메뉴에 탐색 작업을 모았습니다. 상세 패널은 초록·발견 근거·노트 탭으로 나누고, 아카이브에 읽기 상태 필터를 추가했습니다. 탐색 이력과 설정은 전체 작업 화면에서 엽니다.

주요 메뉴와 버튼에 마우스를 잠시 올리거나 키보드로 초점을 옮기면 기능 설명이 표시됩니다. Esc로 닫을 수 있습니다.

단축키: `⌘K` 검색, 입력 중이 아닐 때 `⌘A` 현재 페이지 선택, `⌘S` 선택 저장, `⌘E` 내보내기. 목록 체크박스의 Shift 선택과 그래프의 Shift+드래그를 지원합니다.

실선 화살표는 **인용하는 논문 → 인용된 논문**입니다. `유사 관계`를 켰을 때의 점선은 OpenAlex가 제공한 관련 관계이며 인용 방향을 의미하지 않습니다. 그래프는 현재 범위에서 다른 논문과 연결된 논문만 최대 1,000편, 인용선 3,000개까지 표시하고 연결이 없는 논문은 그리지 않습니다. 서고 폴더에 하위 폴더가 있으면 하위 폴더별로 색을 나눕니다. 표시 범위 밖의 자료는 목록에서 접근합니다.

노드 크기는 현재 그래프 안에서 받은 인용 수를 로그 척도로 반영하며 24~64px 범위로 제한합니다. 관련 문헌 연결과 확인 필요 인용은 집계에서 제외합니다. 필터로 표시 범위가 달라지면 크기도 해당 범위에 맞춰 조정됩니다.

## 원문과 AI 대화

첨부 PDF를 앱 안에서 읽으며 페이지 이동·폭 맞춤·확대·텍스트 선택을 사용할 수 있습니다. `탐색 / 원문`을 전환해도 탐색 상태와 PDF 페이지·확대 비율을 유지합니다. 첨부가 여러 개라면 원문 화면에서 파일을 선택합니다.

오른쪽 `AI` 탭은 탐색 화면에서는 선택 논문의 초록을, 원문 화면에서는 해당 PDF의 추출 본문을 사용합니다. 프로젝트·논문·첨부별로 대화를 분리하고 `대화 기록`에서 이전 대화를 다시 엽니다. `새 대화`는 기존 기록을 보존합니다. 질문·답변·응답 상태·대화에 사용한 원문을 SQLite에 저장하며, 응답 중에도 저장하므로 화면 전환과 앱 재시작 후 기록을 복원합니다.

스캔 PDF의 OCR이나 그림 해석은 지원하지 않습니다. 원문은 100 MiB 이하 파일을 지원하며 AI 본문 추출은 500쪽·200만 글자·60초로 제한합니다. 참고문헌 경계가 불확실하거나 텍스트 없는 페이지가 있으면 안내하고, 추출 실패 시 초록으로 자동 대체하지 않습니다.

## 서고 (이미 정리한 PDF 폴더)

설정의 `서고`에서 NAS 등 이미 정리해 둔 PDF 폴더(예: `/Volumes/LIBRARY/Articles`)를 연결하면, 사이드바 `서고` 아래에 디스크의 폴더 구조 그대로 논문이 보입니다. 색인은 파일을 옮기거나 이름을 바꾸거나 옆에 파일을 만들지 않습니다. 파일을 옮기는 것은 `수신함 정리`에서 승인한 PDF뿐이고, 파일을 지우는 것은 휴지통에서 영구 삭제할 때 `서고 PDF도 삭제`를 고른 문헌의 서고 PDF뿐입니다. 기본값인 `앱에서만 지우기`는 PDF를 폴더에 두고 앱의 서고 목록에서만 뺍니다. 파일은 SHA-256으로 식별해 이동·이름 변경을 따라갑니다. 서고 논문은 모든 프로젝트에서 열람·추천·검색에 쓰이고, `프로젝트에 저장`할 때만 아카이브에 들어갑니다.

- 색인은 파일명(`연도 - 저자 - 제목.pdf`)으로 먼저 보여 준 뒤, 1–2쪽의 DOI와 제목으로 OpenAlex 서지를 확인하고 초록을 채웁니다(OpenAlex → PubMed → PDF). 애매한 파일은 `확인 필요`에서 후보를 고르거나 DOI를 입력합니다.
- 로컬 Ollama의 `embeddinggemma-2`로 초록을 임베딩해 Inspector `관련 문헌` 탭에서 비슷한 서고 논문과 인용으로 이어진 서고 논문을 보여 줍니다. 임베딩과 검색어는 이 Mac 밖으로 나가지 않습니다.
- 앱이 내려받거나 가져와 수신함에 저장한 PDF는 서고 전체를 다시 훑지 않고 몇 초 안에 색인·임베딩합니다. 사이드바 `서고` 옆에 진행 중이면 `임베딩 1/2`, 아직 임베딩하지 못한 논문이 있으면(Ollama가 꺼져 있을 때 등) 흐린 `임베딩 대기 N`이 보이고, 끝나면 다시 편수가 보입니다. 직접 폴더에 넣은 PDF는 30분마다 하는 스캔이나 설정의 `다시 스캔`에서 찾습니다.
- 위쪽 검색창은 지금 화면이 무엇을 찾는지 왼쪽에 표시합니다. `문헌 탐색`에서는 `OpenAlex`만 찾고, 결과 중 이미 가진 논문에는 `서고` 배지가 붙어 필터로 숨기거나 그것만 볼 수 있습니다.
- 사이드바에서 서고나 폴더를 고르면 같은 자리의 검색창이 `내 서고`(또는 폴더 이름) 검색으로 바뀝니다. 네트워크 없이 동작하는 의미 검색입니다. 주제나 질문(한국어도 됨)을 넣고 Enter를 누르면 그 범위에서 관련된 논문을 관련도순으로 보여 주고, 각 행에 `의미가 가까움`·`검색어 일치` 같은 근거를 적습니다. 단어가 들어 있는지로 거르는 일은 `필터`의 포함어·제외어가 맡고, 검색 결과에도 그대로 적용됩니다.
- `PDF 원문 찾기`는 서고에서 먼저 찾습니다. 서고에 있는 논문은 내려받거나 다운로드 폴더에서 복사하지 않고 서고 PDF에 연결만 하며, 서고에 없는 논문만 다운로드합니다. 서고(NAS)가 연결되지 않았을 때도 서고에 있는 논문은 내려받지 않습니다.
- NAS가 연결되지 않아도 서지·초록·추천·검색은 동작하며 PDF 열기만 막힙니다. 이때 파일을 사라진 것으로 처리하지 않습니다.
- `수신함 정리`는 수신함(서고 루트)의 PDF가 갈 폴더를 제안합니다. 이미 분류된 비슷한 논문 20편의 폴더를 로컬 임베딩으로 후보로 삼고, 설정한 AI가 `_system/taxonomy.json`의 정의·포함·배제 규칙을 보고 폴더를 고릅니다. 같은 파일이나 제목·크기가 같은 사본은 `_duplicated`로, 확신이 없는 논문은 `_uncategorized`로 제안합니다. `_uncategorized`로 옮긴 논문은 수신함에서 빠지고 사이드바의 `미분류`에 따로 보이며, 정리 창에서 `미분류 N편도 다시 판정`을 켜면 다시 제안받습니다. 정리 창은 지난 제안이 지금 수신함을 모두 다룰 때만 그 제안을 다시 보이고, 새 PDF가 들어왔으면 수신함 개수와 `제안 만들기`로 시작합니다. 확인한 PDF만 옮기며 파일명은 그대로 둡니다. `_system`이 있으면 `intake.py`와 같은 형식으로 `move_log.jsonl`, `logs/intake-날짜.md`, `index.json`을 갱신합니다. AI에는 제목과 초록(없으면 PDF 첫 쪽 앞부분)만 보냅니다.
- 서고가 연결돼 있으면 앱이 받는 PDF(원문 확보, Chrome 다운로드, 다운로드 파일 복구, 폴더 연결, 직접 첨부, PDF 가져오기)는 모두 서고 맨 위 폴더(수신함)에 `연도 - 저자 - 제목.pdf`로 저장합니다. 서고에 내용이 같은 파일이 있으면 새로 쓰지 않고 연결하며, 서고가 오프라인이면 다운로드와 가져오기를 시작하지 않습니다.
- 설정의 `서고 위치`에서 다른 폴더를 고르면 무엇이 남는지 먼저 보여 주고, 확인한 뒤에 바꿉니다. NAS가 다른 이름으로 다시 마운트됐거나 폴더를 통째로 옮겼을 때, 또는 상위 폴더로 넓힐 때는 기존 색인·서지·임베딩을 그대로 씁니다. 하위 폴더로 좁히면 그 밖의 파일만 색인에서 빼고, 전혀 다른 폴더면 처음부터 색인합니다. 파일은 건드리지 않으며, 색인에서 빠진 PDF에 연결된 프로젝트 논문은 원래 위치의 PDF를 계속 엽니다.

구현 범위와 검증은 [서고 구현 기록](docs/shelf.md)과 [수신함 정리 구현 기록](docs/shelf-sort.md), [수신함 저장 기록](docs/shelf-inbox.md), 설계는 [서고 통합 계획](docs/archive_plan.md)을 참고하세요. 0.3.0의 라이브러리(schema 3)는 0.2.10 이하 앱에서 열리지 않습니다.

## API 설정

설정에서 OpenAlex 키와 연결 상태를 관리합니다. 현재 익명 검색도 동작하지만 공급자의 인증·사용 한도 정책에 따라 키가 필요할 수 있습니다. 키는 Authorization 헤더로 전달합니다.

AI 추천과 sidebar 대화는 **실험 기능**입니다. 새 설정의 기본 연결은 `Ollama Cloud`의 `gpt-oss:120b`이며 기존에 선택한 연결은 유지합니다. 설정에서 Ollama 키·모델을 지정하거나 `Codex (ChatGPT subscription)` 또는 `OpenAI API`를 선택합니다. Codex 연결은 설치된 공식 Codex CLI를 사용하며 `ChatGPT로 로그인`으로 연결합니다. ResearchBunny 전용 로그인은 `~/Library/Application Support/ResearchBunny/codex`에 저장하고 라이브러리 백업에는 넣지 않습니다. 계정 기본 모델 또는 계정에서 제공하는 모델을 선택할 수 있습니다.

사용자가 AI 추천을 실행하면 연구 질문과 후보의 제목·초록을 선택한 공급자에 보냅니다. Sidebar 대화에서는 현재 화면의 초록 또는 추출한 PDF 본문과 해당 thread의 대화 기록을 보냅니다. 개인 노트는 보내지 않습니다. 대화의 검색 옵션은 기본적으로 꺼져 있으며 켜면 OpenAlex·PubMed, 결과가 부족한 경우 설정된 TinyFish를 통해 추가 근거를 찾습니다. 구독 연결은 호출마다 포함 사용 허용 상태와 한도를 확인하며, 확인 실패·한도 소진 시 중단합니다. 유료 API로 자동 전환하지 않습니다. 여러 앱이 계정 한도를 공유하므로 이 사전 확인은 서버 차원의 추가 과금 차단을 보장하지 않습니다. Codex에는 실행당 3회 호출 및 입력 예산을 적용하며 API의 응답 토큰·달러 상한은 지원하지 않습니다.

기존 키와 API 모델·예산은 보존되며 `OpenAI API · 별도 API 과금`을 직접 선택했을 때만 사용합니다. API 요금 입력값은 사용자가 확인하는 예상 비용 기준입니다. 구현 범위와 검증 기록은 [마이그레이션 문서](docs/codex-subscription-migration.md)를 참고하세요.

새 API 키는 macOS 키체인에 저장하며 평문 DB·renderer·백업에 포함하지 않습니다. Electron의 기존 `credentials.json`은 그대로 보존합니다. 기존 키가 있는 경우 설정 화면 안내에 따라 한 번 다시 입력하세요. 키체인 접근이 실패하면 저장을 차단합니다.

실제 OpenAI 호출과 사람이 판정하는 추천 품질 평가는 아직 수행하지 않았습니다. 식별자·인용문 검증은 의미적 타당성이나 논문의 중요도를 보증하지 않습니다. AI를 설정하지 않아도 검색·탐색·아카이브·내보내기를 사용할 수 있습니다.

## 파일과 데이터 보존

기본 위치는 `~/Library/Application Support/ResearchBunny/`입니다. 설정 화면에 현재 라이브러리의 정확한 위치가 나옵니다.

| 경로                     | 내용                                    |
| ------------------------ | --------------------------------------- |
| `library/library.sqlite` | 문헌·프로젝트 상태·노트·관계·작업 기록·AI 대화와 문맥 |
| `library/attachments/`   | SHA-256으로 식별한 관리 PDF 사본        |
| `credentials.json`       | 보존된 Electron 암호화 키 파일. 새 키는 macOS 키체인에 저장 |
| `library-location.json`  | 복원 후 현재 라이브러리 위치            |
| `libraries/restored-…/`  | 기존 라이브러리와 분리해 검증한 복원본  |

PDF 기본값은 앱 관리 폴더로 복사입니다. 기존 위치 연결과 서지정보만 가져오기도 지원합니다. 원본 파일은 수정·이동·삭제하지 않습니다. 파일 해시가 같으면 중복 첨부를 만들지 않습니다. 메타데이터·첫 페이지 추출은 별도 프로세스에서 파일당 15초로 제한하며 100MB 초과 파일은 텍스트 추출을 생략합니다. 스캔·암호화·부정확한 서지는 대기함에서 직접 수정하거나 기존 문헌에 연결하세요. OCR은 포함하지 않습니다.

가져오기 기록의 `파일별 결과 보기`에서 실패 이유를 확인하고 실패 파일을 재시도할 수 있습니다. 외부 연결 파일을 옮겼으면 상세 패널의 재연결을 사용합니다. 휴지통 이동은 복구 가능하며 자동 영구 삭제는 하지 않습니다.

설정의 백업은 SQLite의 일관된 스냅샷(`VACUUM INTO`)과 선택한 첨부를 **백업 폴더**로 만듭니다. 외부 연결 파일 포함 여부도 선택할 수 있습니다. manifest와 SHA-256 검증 후 별도 공간에 복원하고 현재 라이브러리를 전환합니다. 기존 라이브러리는 남습니다. 누락 첨부는 보고하고 재연결이 필요한 상태로 표시합니다. 실행 중인 `.sqlite` 파일만 임의로 복사하면 WAL 변경을 빠뜨릴 수 있으므로 앱 백업을 사용하세요.

아카이브와 분류 화면의 **PDF 원문 찾기**는 전체 아카이브·현재 분류/컬렉션·선택 문헌의 공개 원문을 확보해 기존 논문에 첨부합니다. 파일은 기존처럼 SHA-256 해시로 보관하며 분류·노트·읽기 상태를 유지합니다. 이미 보관한 PDF는 건너뛰고 책·챕터는 기본 제외합니다. 작업 기록에서 실패 항목을 재시도하거나 원문 페이지를 열고 PDF를 직접 연결할 수 있습니다. 로그인·사람 인증 자동 처리는 포함하지 않습니다. [구현 및 검증 기록](docs/fulltext-download.md)을 참고하세요.

## 작업 범위와 한도

- 탐색은 사용자가 요청한 한 단계씩 실행합니다. 일반 실행은 40회 호출·후보 1,000편, AI 수집은 후보 500편부터 시작합니다. 추가 조회·재개는 별도 사용자 동작입니다.
- 호출 상한과 페이지 중간 체크포인트를 보존합니다. 취소·오류·재시작 후 이미 저장한 후보는 유지합니다. 앱을 완전히 종료한 동안에는 작업하지 않습니다.
- OpenAlex의 누락과 잘못된 메타데이터가 존재할 수 있습니다. 공통 관계 수는 확보한 출발 문헌·이웃 안의 집계입니다. 분야 전체의 완전한 네트워크가 아닙니다.
- 관련성 점수와 엄격도는 `tfidf-topic-v1` 임시 기준선입니다. 서로 다른 실행의 점수를 절대 척도로 비교하지 않습니다.
- P1–P3의 동기화·알림·OCR·자동 문헌고찰·협업은 포함하지 않습니다.

## 개발과 검증

Bun 1.3.8, npm, Xcode Command Line Tools가 있는 macOS 환경에서:

```sh
npm ci
bun run start
bun run typecheck
bun run lint
bun run test
bun run package
bun run test:desktop
bun run test:live
```

개발에는 Bun 1.3.8, npm, Xcode Command Line Tools가 필요합니다. `npm ci`는 고정된 의존성을 설치합니다. `bun run package`는 WebKit 앱·로컬 서명·DMG를 생성합니다. 배포 앱은 Bun·SQLite·PDF 처리 리소스를 포함하므로 사용자의 Node/Python/PATH에 의존하지 않습니다.

`test:desktop`은 패키지의 압축이 풀린 상태에서 번들 런타임·PDF 추출·저장·내보내기·백업/복원을 검사합니다. WKWebView와 macOS 파일 대화상자는 별도로 실제 앱에서 확인합니다. 전환 내용과 검증 범위는 [마이그레이션 기록](docs/electrobun-migration.md)을 참고하세요.

별도의 QA 데이터로 UI를 확인하려면 다음처럼 전용 앱을 빌드합니다. QA 경로는 패키징 결과 폴더(`out/electrobun`) 밖에 두세요.

```sh
RESEARCHBUNNY_BUILD_QA_ROOT="$PWD/.qa/ui" bun run build
open build/dev-macos-arm64/ResearchBunny-QA-dev.app
```

일반 배포 빌드에는 `RESEARCHBUNNY_BUILD_QA_ROOT`를 지정하지 않습니다. `test:desktop`은 `bun tests/desktop/electrobun-smoke.ts /absolute/path/ResearchBunny.app`처럼 다른 위치의 압축 해제된 앱도 검사할 수 있습니다.

실제 API 테스트는 공개 문헌 조회를 수행합니다. 자동 테스트는 임시 라이브러리를 사용합니다. `RESEARCHBUNNY_DATA_DIR` 환경 변수로 개발 데이터 위치를 분리할 수 있습니다. 정상 사용자의 자료에 테스트 fixture를 넣지 않습니다.
