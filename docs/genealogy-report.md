# 컬렉션 계보 리포트 구현 기록

[계획](genealogy-report-plan.md)의 단계별 구현과 검증을 적는다. 계획과 달라진 결정은 각 단계에 밝힌다.

## M1 · 자료 준비 (2026-10-25)

### 만든 것

- **들어가는 곳**: 컬렉션 화면 머리의 `계보 리포트` 버튼. 그 컬렉션의 리포트가 있으면 열고, 없으면 만들기 대화상자를 연다. 만든 리포트는 사이드바 `계보 리포트` 묶음에 보인다.
- **만들기 대화상자**: 제목, 연구 질문(프로젝트 질문 또는 최근 seed 질문으로 미리 채움), 독자, 단계별 AI 연결(유형·후보 판정 / 문헌 카드 / 가지 장부·목차·집필), 새 논문 자동 반영 방식과 예산, 목차 승인 지점, PDF 내려받기·Chrome 사용, 호출 상한·동시 처리 수, CSL, 작업 폴더.
- **작업 화면**: 단계 표시(자료 준비 → 문헌 카드 → 공백 점검 → 가지 장부·목차 → 집필 → 검증 → 렌더)와 단계별 단독 실행, `시작`/`이어서 진행`/`멈추기`, 진행 막대와 AI 호출 수, `문헌`·`설정` 탭, 작업 폴더 열기.
- **자료 준비 단계**
  1. 컬렉션 구성원을 계보 문헌으로 맞춘다. 컬렉션에서 빠진 문헌은 카드를 남긴 채 제외 표시만 한다.
  2. 참고문헌 목록이나 OpenAlex ID가 없는 문헌을 OpenAlex에서 100편씩(DOI는 50편씩) 보강한다.
  3. Europe PMC 검색으로 DOI·PMID에서 공개 전문 PMCID를 찾는다. OpenAlex는 더 이상 PMCID를 주지 않는다(2026-10-25 확인).
  4. 유형(R/M/O/P): PubMed 출판 유형과 OpenAlex `review`로 먼저 정하고, 모든 문헌을 25편씩 작은 모델에 보여 빈 곳을 채우고 주변 문헌(P)을 고르게 한다. 서지 정보가 정한 유형은 힌트로 함께 보낸다. 사용자가 고친 유형은 다시 판정하지 않는다.
  5. PDF도 PMC 전문도 없는 문헌은 기존 `PDF 원문 찾기` 작업(서고 연결 → 공개 원문 → Chrome → 설정한 Sci-Hub 미러)을 `selected` 범위로 실행하고 끝날 때까지 기다린다. 서고가 오프라인이거나 다른 원문 작업이 돌고 있으면 건너뛴다.
  6. 읽을 본문: PMC 전문은 JATS의 `sec-type`과 절 제목으로, PDF는 pdf.js 본문에서 참고문헌을 떼고 절 제목 줄로 자른다. 서론 제목이 없으면 초록 뒤 본문이나 첫 절 앞 본문을, 절을 하나도 못 찾으면 앞 25%를 서론으로 읽고 그 사실을 기록한다. 추출 결과는 첨부 해시나 PMCID 기준으로 `genealogy_texts`에 캐시한다.
  7. 유형별 읽기 범위: 종설은 본문 전체, 메타분석은 초록·서론·논의, 원저는 초록·서론·논의 앞 900단어·결론, 주변 문헌은 초록과 서론 앞 700단어.

### 계획과 달라진 점

- 스키마 번호를 올리지 않았다. 계보 표는 `project_opens`처럼 곁 표(side table)라 0.3.x 앱도 라이브러리를 그대로 연다. 프로젝트·컬렉션·문헌을 지우면 연쇄 삭제되고, 문헌 병합은 계보 행과 카드를 남는 문헌으로 옮긴다(병합 되돌리기에도 포함).
- 작업 상태는 `runs`가 아니라 계보 행 자체(`job`)에 둔다. 탐색 기록 화면과 섞이지 않게 하려는 것이다. 앱을 끄면 진행 중이던 작업은 `중단됨`이 되고 `이어서 진행`으로 다시 시작한다. 구독 한도·OpenAlex 한도는 `일시정지`, 그 밖의 오류는 `실패`.
- 진행 이벤트는 `{ type: "genealogy", id }`로 따로 보내 작업 화면만 다시 읽게 했다.

### 검증

- 통합 시험 `tests/integration/genealogy-prepare.test.ts` 8개: JATS 절(표·참고문헌 제외), PDF 절 나누기(번호·대문자 제목, 추정 표시), 유형별 읽기 범위, 서지 유형 판정과 PMCID 정규화, 자료 준비 전체 흐름(OpenAlex 보강, Europe PMC 검색, PubMed 출판 유형, AI 판정, JATS·PDF·초록), 컬렉션 동기화·병합·사용자 유형 지정, 원문 확보 작업 호출과 대기, 구독 한도 → 일시정지.
- 실제 화면(QA 라이브러리, 실제 React 화면과 서비스): 환각제 기전 논문 6편을 OpenAlex에서 받아 컬렉션을 만들고 리포트를 만들어 자료 준비를 실행했다. Europe PMC에서 4편의 공개 전문을 받아 절을 나눴고(예: 엔트로피 뇌 가설 본문 89,567자), 2편은 공개 전문이 없어 초록만 읽었다(이 QA에서는 PDF 내려받기를 껐다). AI 응답은 QA용 가짜 응답기였다.

## M2 · 문헌 카드 (2026-10-25)

### 만든 것

- `문헌 카드` 단계: 카드가 없거나(새 문헌), 유형·읽은 범위가 바뀌었거나, 지난번에 실패한 문헌만 다시 읽는다. 설정의 동시 처리 수만큼 함께 읽고, 구독 한도에 걸리면 모든 작업을 멈추고 단계를 일시정지한다. 개별 실패는 그 문헌에 이유를 남기고 나머지를 계속한다.
- 카드 필드는 계획의 스키마와 같다(계보 위치, 문제제기, 주장, 근거와 원문 인용, 해석·방법론 비판, 미해결, 자금·이해상충·학파, 계보상 의의, 앞선 연구와 그 역할, 가지 상태 신호, 주의). 인용문과 앞선 연구 표기만 원문 그대로, 나머지는 한국어.
- 근거 검증: 인용문이 읽힌 본문의 부분 문자열인지 확인한다(공백·줄바꿈 하이픈·따옴표 정규화). 맞지 않는 근거는 빼고 주의에 적는다. 절반 넘게 맞지 않으면 답을 거절하고 한 번 다시 요청한다. 근거 설명의 숫자가 본문에 없으면 주의에 적는다.
- 긴 종설: 읽을 본문이 15만 자를 넘으면 문단 경계에서 나눠 부분 카드를 만들고, 한 번 더 호출해 하나로 합친다.
- 작업 폴더의 `cards/NNN_citekey.md`: 출판 연도 순 번호, 스킬의 카드 양식. 리포트에서 빠진 문헌의 카드 파일은 지운다(카드 자체는 DB에 남는다).
- 문헌 탭에서 행을 열면 카드 전체가 보인다.

### 계획과 달라진 점

- 기계용 카드 JSON 파일(`cards/*.json`)은 만들지 않았다. 카드는 DB에 두고, 작업 폴더에는 사람이 읽는 Markdown만 쓴다.

### 검증

- 통합 시험 `tests/integration/genealogy-cards.test.ts` 4개: 인용문 대조와 수치 확인, 문단 분할, 카드 단계 전체(분할·병합, 두 번 실패한 문헌 기록, 파일 이름과 내용, 화면용 카드 목록), 한도 도달 시 모든 작업 정지와 일시정지.
- 실제 화면(QA 라이브러리): 6편의 카드를 만들고 문헌 탭에서 카드를 열었다. PMC 전문에서 고른 근거 인용문이 원문 대조를 통과했고 `cards/001_….md`부터 6개 파일이 생겼다. AI 응답은 QA용 가짜 응답기였다.

## M3 · 공백 점검, 가지 장부, 상세 목차 (2026-10-25)

### 만든 것

- `공백 점검` 단계: 세 가지 신호로 컬렉션에 없는 논문을 찾는다.
  - 공통 참고문헌: 계보 문헌의 OpenAlex 참고문헌 목록을 세어, 문헌 수의 10%(최소 2편) 이상이 함께 인용하는 문헌. 종설·메타분석의 인용은 1.5배로 센다. 상위 80편.
  - 카드 속 언급: 카드의 `앞선 연구`(예: "Tononi and Edelman (1998)")를 그 논문의 참고문헌 목록 안에서 1저자 성과 연도(±1)로 찾는다. 번호만 있는 언급은 찾지 않는다.
  - 최근 후속 연구: 계보 문헌을 50편씩 묶어 그 문헌들을 인용하는 최신 논문 600편까지 보고, 계보 문헌의 15%(최소 2편) 이상을 인용하는 논문. 이때 계보 문헌마다 최근 인용 수도 세어 가지 장부의 근거로 넘긴다.
  - 점수가 높은 후보(최대 60편)를 작은 모델이 연구 질문에 비춰 판정한다(출발점·전환점·반박·최신 정리·방법·최근 진전·무관, 관련도, 한 줄 이유). 무관은 0점.
- `추가` 탭: 후보를 점수순으로 보이고 채택·제외·되살리기를 한다. 채택하면 아카이브에 있는지, 서고에 있는지 보고 없으면 OpenAlex에서 받아 컬렉션과 아카이브에 넣는다. 리포트가 넣은 문헌은 출처·차례·이유와 함께 따로 보이고 `되돌리기`로 컬렉션(그리고 리포트가 처음 넣었다면 아카이브)에서 뺀다. 이 단계의 반영 방식은 수동이다. 설정의 `자동 채택`은 M5에서 동작한다.
- `가지 장부·목차` 단계
  1. 인용 기록 묶음: 계보 문헌 사이의 인용, 직접 인용·공유 참고문헌으로 묶은 군집(결정적 레이블 전파), 군집의 활동 연도, 문헌별 최근 인용 수.
  2. 가지 장부: 카드 요지(의의·주장·비판·가지 상태 신호·앞선 연구)와 인용 기록으로 가지마다 출발 문헌, 주장, 전환점, 상태(살아남음·막힘·합류·휴면·논쟁 중), 상태의 근거, 막힌 이유, 마지막 활동 연도를 정한다.
  3. 상세 목차: 가지 장부를 뼈대로 장·절, 장과 절의 논지, 다룰 질문, 가를 증거, 기대는 문헌, 가지를 정한다. 첫 답에서 문헌의 10% 넘게 어느 절에도 없으면 다시 요청하고, 두 번째 답에서는 빠진 문헌을 완료 메시지에 알린다.
  4. 작업 폴더에 `00_contents.md`(장 `##`, 절 `###`, 절마다 `<!-- rb:section keys=… branches=… -->`와 논지·질문·증거 줄)와 `부록A_가지_장부.md`를 쓴다.
  5. 설정의 `목차 승인 지점`이 켜져 있으면 여기서 일시정지한다.
- `목차` 탭: 가지 장부 표와 목차. `목차 고치기`로 `00_contents.md`를 앱에서 고치거나, 다른 편집기에서 고친 파일을 `고친 파일 읽기`로 읽어 온다. 다시 읽을 때 장·절 번호를 새로 매기고, 바뀌지 않은 절은 집필 상태를 이어받는다. `목차 승인`.

### 검증

- 통합 시험 `tests/integration/genealogy-outline.test.ts` 6개: 언급 해석(성·연도, 번호 언급, 악센트), 공통 참고문헌 가중치와 점수, 군집, 목차 키 검사·빠진 문헌 보고·`00_contents.md` 왕복(절 추가·제목 변경·상태 승계), 공백 점검 전체(세 신호, 최근 인용 수, 후보 판정, 채택·되돌리기·제외의 아카이브 상태), 목차 단계(가지 장부, 파일, 승인 대기, 고친 파일 읽기, 승인).
- 실제 화면(QA 라이브러리): 6편으로 공백 점검을 돌려 실제 OpenAlex 기록에서 후보 100편을 얻었다. 상위에는 Friston 2010(자유에너지 원리, 계보 문헌 4편이 함께 인용, 카드 언급과도 일치), Vollenweider 1998, Griffiths 2011 같은 기반 연구가 올랐다. 가지 장부 3개와 4장 5절 목차가 만들어졌고 승인 대기에서 멈췄다. 목차 편집기를 열어 보았다. AI 응답은 QA용 가짜 응답기였다.

## M4 · 집필, 검증, bib, EPUB·PDF (2026-10-25)

### 만든 것

- `목차` 탭의 `승인하고 집필 시작`: 승인한 뒤 집필 → 검증 → 렌더를 이어서 실행한다.
- `집필` 단계: 시작할 때 다른 편집기에서 고친 `00_contents.md`를 먼저 읽는다. 목차 순서대로 `쓸 차례`·`다시 쓸 차례`인 절만 한 번씩 호출한다. 입력은 전체 목차와 요지, 장·절의 논지와 질문·증거, 관련 가지, 절이 기대는 문헌의 카드 전문, 같은 장 다른 문헌의 의의, 앞 절들의 세 문장 요약, 인용 가능한 키 목록이다. 집필 지침은 계획 6장과 같다(논지 먼저, 주장 → 반론 → 가르는 증거, 실험은 질문·결과·배제한 것만, 가지 상태, 독자 기준 용어 풀이, 카드의 숫자만, `[@key]`만, 없는 근거는 `missingSources`로 요청).
  - 검사: 첫 답에서 목록 밖의 키나 번호 인용(`[3]`)이 있으면 거절하고 다시 요청한다. 두 번째 답에서는 그 인용을 빼고 절에 기록한다. 카드에 없는 수치(%·명·편 등이 붙은 수, 소수)는 기록만 한다.
  - 절 원고는 DB에 절 고유 ID로 두고, 장마다 `NN_장제목.md`(`# N. 제목`, `**요지.** 장 논지`, `## N.M 절`)로 쓴다. 사용자가 고친 장 파일은 덮어쓰지 않고 새 판을 `NN_장제목.rb-new.md`로 옆에 둔다. 목차에서 빠진 장의 파일은 사용자가 고치지 않았을 때만 지운다.
  - 절마다 `다시 쓰기`가 있다(그 절만 `다시 쓸 차례`로 바꾸고 집필 단계를 실행).
- `검증` 단계: 디스크의 장 파일(사용자 수정 포함)을 기준으로 스킬의 점검 목록을 돈다. 모든 절을 썼는가, 인용 키가 모두 계보 문헌인가(= bib에 들어가는가), 번호·평문 인용이 없는가, pandoc 시험 렌더에서 해석되지 않는 인용이 없는가, 계보 문헌이 모두 본문에 나오는가, 수치가 카드에 있는가, 배타적·비교 주장(최초·유일·only·first) 문장, 집필 중 요청한 근거, 집필 검사에서 고친 것, 직접 고친 장 파일.
- `렌더` 단계
  - 본문에서 인용한 문헌만 `<제목>.bib`로 내보낸다(`exportBib`). 저자는 "성, 이름"으로 바꿔 넣어 양식이 이름을 줄일 수 있게 했다(OpenAlex 표기 "Robin L. Carhart-Harris" → "Carhart-Harris, Robin L."). 가져온 bib의 저자 필드는 그대로 둔다.
  - CSL: 설정에 파일이 없으면 직접 쓴 기본 양식 `vancouver.csl`(등장 순서 번호 `[1]`, NLM/Vancouver형 참고문헌, 6명 넘으면 et al., 문서 언어와 관계없이 영문 용어)을 작업 폴더에 둔다.
  - `build/<제목>.md`: YAML(title, subtitle, date, `lang: ko`, bibliography, csl, `reference-section-title: 참고문헌`, `link-citations: true`), 리포트 요지, 장 파일들, 부록 A 가지 장부.
  - EPUB: `pandoc -f markdown-smart --citeproc --toc --split-level=1`과 본문 CSS.
  - PDF: `pandoc --pdf-engine=typst`, A4, 10.5pt, 글꼴은 typst가 찾는 것 중 Noto Serif CJK KR → NanumMyeongjo → Noto Serif KR → AppleMyungjo. pandoc·typst는 Homebrew·`/usr/local/bin`·Quarto 번들에서 찾고, 없으면 Markdown과 bib만 만들고 설치 방법을 알린다.
- `본문` 탭: 장 목록(절 진행 수), 절별 상태·검사·근거 요청 표시와 다시 쓰기, 원고 미리보기(인용을 리포트 전체 등장 순서의 번호로 바꿔 보여 줌)와 그 장의 인용 문헌 목록.
- `검증·내보내기` 탭: 검증 실행, EPUB·PDF 만들기, EPUB·PDF·Markdown·bib 열기, 도구 경로, 점검 목록.

### 검증

- 통합 시험 `tests/integration/genealogy-write.test.ts` 5개: 인용 키 추출(괄호·서술형·쪽 표시·이메일·끝 구두점)과 제거·번호 매기기, 절 검사(거절 → 정리, 번호 인용, 수치, 너무 짧은 답), 저자 "성, 이름" 변환, 집필 → 검증 → 렌더 전체(앞 절 요약 전달, 장 파일 형식, 근거 요청, bib, YAML, 이 Mac의 실제 pandoc 3.11·typst로 EPUB·PDF 생성과 citeproc 경고 0), 사용자가 고친 장 파일 보존과 `.rb-new.md`, 절 다시 쓰기, 검증의 미해결 키·직접 고친 장.
