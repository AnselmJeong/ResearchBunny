## 계획과 다르게 정한 점

- **`stage`에서 `embedded`를 뺐다.** 임베딩 여부는 `work_embeddings`(모델 digest·프롬프트 버전·입력 해시)로만 판단한다. 모델이나 프롬프트를 바꾸면 단계 값을 고치지 않아도 자동으로 다시 만든다.
- **새 RPC를 줄였다.** `shelfScan`은 `shelfControl({ action: "scan" })`, `shelfTree`는 `snapshot.shelf`, `shelfReview`는 `shelfFile`로 합쳤다. `shelfControl`에 `reresolve`(확인 필요 다시 조회)와 `confirmMissing`(대량 사라짐 반영)을 더했다.
- **서고 루트는 하나다.** 경로를 바꾸면 같은 루트를 새 위치로 옮기고(재마운트 대비) 첨부 경로만 고친다. 파일 ID와 서지는 유지된다.
- **원문 확보의 서고 연결은 비파괴적으로 했다.** 제목만 일치한 프로젝트 논문에는 서고 PDF를 가리키는 `linked` 첨부를 하나 더 붙인다. 서고 쪽 기록은 그대로 둔다. DOI 같은 강한 식별자가 같으면 원래대로 한 work로 합쳐진다.
- **사본(같은 해시)의 상태는 `ok`로 둔다.** 사본의 서지는 원본 파일이 결정하므로, 확인 필요 수에는 원본만 센다.
- **서고 목록에서 행을 누르면 Inspector만 연다.** NAS 파일 전체를 읽는 원문 보기는 `원문 보기`로 연다(계획 6.1과 같음). 다른 목록은 기존처럼 원문을 연다.
- **병합 되돌리기용 스냅샷에는 두 work의 서고 행만 넣는다.** 벡터 BLOB 전체를 JSON 스냅샷에 넣지 않기 위해서다. 되돌린 뒤 FTS를 다시 만든다.
- **바로 반영하지 않고 확인받는 대량 사라짐 기준**은 활성 파일 5개 이상이면서 20% 초과다(작은 서고에서도 동작하도록).

## 동작 요약

- 색인은 48편 단위로 해시(동시성 2) → 추출(동시성 3, 1–2쪽) → 서지 확인 → 임베딩(32개 묶음)을 거친다. 진행 상태가 행마다 남아 앱을 다시 켜거나 취소해도 이어서 처리한다. 앱이 켜져 있는 동안 30분마다 다시 스캔한다.
- 새 파일은 스캔 직후 파일명 기반 임시 서지로 바로 보인다. 250개씩 커밋해 첫 스캔 중에도 화면이 멈추지 않는다.
- 서지 확인: 앱이 관리하던 PDF와 해시가 같으면 그 work, 아니면 1–2쪽 DOI 후보를 50개씩 묶어 조회하고 파일명 제목 유사도 0.5 이상만 받는다(인용 문헌 DOI 방지). 그 다음은 제목·연도 검색으로, 유사도 0.9 이상이면서 첫 저자가 같아야 받는다. 0.75–0.9이거나 저자가 다르면 `확인 필요`로 둔다.
- 초록: OpenAlex → PubMed `efetch` → PDF 추출 순서. PDF에서 뽑은 초록은 Inspector에 표시한다.
- OpenAlex 일일 예산·한도·연결 오류는 서지 확인 단계만 멈춘다. 한도가 풀리면 자동으로 이어서 스캔한다.
- 서고가 없거나 스캔·해시·추출 중 연결이 끊기면 어떤 파일도 `missing`이나 `failed`로 바꾸지 않는다.
- 원문 확보는 서고를 먼저 본다. 작업을 시작하면 Chrome·다운로드 폴더 복구·네트워크보다 먼저 서고에 있는 논문을 모두 연결하고(파일 복사·다운로드 없음), 서고에 없는 논문만 내려받는다. 서고에 있는지는 그 논문의 서고 파일, 같은 DOI(제목 유사도 0.5 이상), 같은 제목, 또는 순서·불용어·문장부호만 다르고 첫 저자가 같은 제목으로 판단한다(DOI 충돌 없음, 연도 ±1). 서고(NAS)가 연결되지 않으면 작업을 시작하지 않는다(내려받은 PDF도 서고 수신함에 저장하기 때문, [수신함 기록](shelf-inbox.md)). 작업 중에 끊겨 서고 PDF를 검증할 수 없을 때도 내려받지 않고 `서고 연결을 확인하세요`로 남긴다.
- 검색: DOI·PMID·OpenAlex ID는 식별자로 바로 찾고, 그 밖의 질의는 FTS5 BM25(제목 3, 저자 2, 초록 1, 학술지 0.5)와 벡터 검색을 RRF(k=60)로 합친다. Ollama가 꺼져 있으면 어휘 검색만 한다.
- 서고 목록 검색: 서고 화면의 검색 칸은 위 하이브리드 검색을 지금 폴더(하위 폴더 포함) 범위로 실행해 최대 200편을 관련도순으로 보여 준다. 질의 임베딩이 필요하므로 입력마다가 아니라 Enter로 실행한다. 다른 목록의 검색 칸은 지금처럼 부분 문자열 필터다. 어휘 검색은 OR로 묶으므로 영어 기능어(`of`, `the`, `in` 등)는 질의에서 뺀다.
- 임베딩과 검색어는 로컬 Ollama(기본 `127.0.0.1:11434`)에서만 처리한다. 다른 주소를 넣으면 설정에 경고가 뜬다.

## OpenAlex 사용량

OpenAlex는 요청을 크레딧으로 센다(2026-10-11 응답 헤더 기준). 검색(`search=`, `title.search`, `title_and_abstract.search`)은 10크레딧(US$0.001), 필터 조회(DOI 50개 묶음)는 1크레딧이다. 일일 한도는 UTC 자정(한국 시간 09:00)에 초기화된다.

- 서고 색인은 응답 헤더의 잔액을 보고, 남은 예산이 20% 아래면 서지 확인을 멈춘다. 남은 몫은 앱의 일반 검색에 쓰인다. 예산이 초기화되면 이어서 확인한다.
- 일일 한도 오류(429)는 헤더의 `x-ratelimit-reset`까지 기다린다. 남은 크레딧이 요청 비용(`x-ratelimit-credits-required`)보다 적어서 거절된 경우도 일일 한도로 본다. 묶음 처리 중 멈춰도 이미 받은 결과는 반영한다.
- 멈춘 시각과 이유는 DB(`preferences`의 `shelf:resolverPause`)에 저장한다. 앱을 다시 열어도 그 시각까지는 OpenAlex를 부르지 않고, 이후 서지 확인을 기다리던 파일부터 이어서 한다. 기다리는 파일은 `확인 필요`에 넣지 않고 `서지 확인 대기`로 따로 센다.
- 서고를 읽을 수 없으면(마운트 직후, 권한 대기) 30분이 아니라 2분 뒤에 다시 스캔한다.
- 실제 첫 색인에서는 제목 검색 약 1,000회로 하루 예산을 다 썼다. 이 수정 전 빌드였기 때문에 그날 남은 시간 동안 앱의 OpenAlex 검색도 막혔다.

- `typecheck`, `lint` 통과. 통합 테스트 **171개 통과, 실패 0개** (기존 162 + 서고 9). 서고 테스트는 세 번 반복해도 결과가 같았다.
  - 서고 테스트 범위: 읽기 전용(파일 목록·크기·mtime 불변), DOI 채택과 인용 DOI 함정, 제목 검색 채택·보류, 보충자료, 같은 해시 사본, 제외 폴더, 이동·이름 변경·사라짐, 오프라인 보호, 대량 사라짐 확인, 유사 논문·인용 연결·즉석 임베딩, 하이브리드 검색과 Ollama 중단 시 어휘 검색, 탐색 실행의 서고 작업·고정 묶음·필터·API 0회, 다운로드 없이 서고 PDF 연결, 영구 삭제 후에도 서고 work 유지, 병합과 되돌리기, 프로젝트 밖 서고 PDF 열람, AI 근거 순서, schema 2→3 업그레이드.
- 패키지 빌드 후 압축을 푼 앱으로 `test:desktop` 통과.
- 성능(`tests/integration/shelf-performance.ts`, 서고 10,000편·인용 50만 행): 400편 폴더 목록 12 ms(예산 300), 서고 전체 목록 113 ms(예산 1,500), 관련 문헌 23 ms(예산 150), 어휘 검색 6 ms, 벡터 적재 31 ms, 화면 500편 인용선 96 ms. 기존 아카이브 5,000편 목록 p95는 main 208 ms → 114 ms.
- 실제 서고 표본(`11 Philosophy…/History of Psychiatry & Neuroscience`, 30편, 별도 QA 라이브러리): 색인 11초, OpenAlex 7회. 29편 서지 확인(DOI 24, 제목 검색 5), 1편 파일명 서지. 초록 28편(OpenAlex 21, PubMed 7), 2편은 1쪽 텍스트로 임베딩. 색인 전후 폴더 파일 목록·크기·mtime 동일. 다시 스캔 시 API 0회. 검색 23–27 ms, 관련 문헌 2 ms. 이 속도면 8,322편 첫 색인은 약 50분으로 추정된다.
- 실제 서고 전체(2026-10-11 설치본): 8,295개 파일(제외 폴더 `_duplicated` 27개 빼고)을 1분 안에 등록했다. 해시·추출·임베딩은 57분에 모두 끝났다. 서지 확인은 7,157개 중 7,031개 성공(DOI 6,165, 제목 검색 855, 앱 관리 PDF와 같은 해시 5, 사본 6)으로 98.2%였다. 확인 필요 36개, 파일명 서지 87개, 보충자료 3개다. 나머지 1,138개는 OpenAlex 일일 예산 때문에 다음 날로 넘겼다. 임베딩 8,212개(초록 6,666, PDF 초록 562, 1쪽 979, 제목 5). 기존 프로젝트 아카이브 논문 115편이 DOI로 합쳐져 서고 PDF가 붙었다.
- 화면 확인: 실제 renderer를 QA 라이브러리에 연결해 서고 트리, 서고 목록·배지, Inspector 서고 정보와 `관련 문헌`·`발견 근거` 탭, 한국어 `서고만 검색`의 고정 묶음, 설정의 서고 구역을 확인했다. 네이티브 WebKit 창 확인과 설치 앱 교체는 하지 않았다.

## 정해진 사항

- **프롬프트 형식**: [EmbeddingGemma 2 모델 카드](https://ai.google.dev/gemma/docs/embeddinggemma/model_card_2)의 검색 형식(문서 `title: {title} | text: {content}`, 제목이 없으면 `title: none`, 질의 `task: search result | query: {query}`)과 구현이 같다.
- **모델**: 설치된 `embeddinggemma-2:latest`를 그대로 쓴다. `270m`으로 바꾸지 않는다(2026-10-11 결정). 이 태그는 Ollama MLX 실행기의 `nvfp4`(4비트) 양자화이고, 모델 카드는 bfloat16·float32 추론을 기준으로 한다.
- **레코드 크기**: OpenAlex로 확인한 서고 work는 `raw`를 줄여 평균 4.4 KB(최대 8.2 KB)다. 기존 아카이브 work는 평균 32.7 KB다. 스냅샷까지 합쳐 8,322편이면 DB가 약 70 MB 늘어난다.

## 남은 일

1. **임베딩 품질 평가 (폴더 일치율@10)**: 사용자가 만든 말단 폴더를 정답으로 보고, 각 논문의 상위 10개 이웃 중 같은 폴더 비율을 잰다. 질의 30개를 직접 판정한 소규모 검색 평가도 함께 한다. 이 결과로 두 가지를 정한다.
   - 검색의 의미 결과 하한. 지금은 코사인 0.65 이상, 최고점과의 차이 0.1 이내다. 손으로 고른 몇 쌍(관련 0.69–0.85, 무관 0.47–0.66)만 보고 정한 임시값이고, 모델 카드에도 권고값이 없다.
   - `관련 문헌` 탭의 벡터. 지금은 검색용 문서 벡터끼리 비교한다. 모델 카드는 유사도 작업에 대칭 접두어(`task: sentence similarity | query: …`)를 권한다. 바꾸면 논문마다 벡터를 하나 더 저장해야 한다.
2. **서지 확인 표본 200편**: 11개 도메인에서 고르게 뽑아 DOI 채택률, 제목 검색 채택률, 초록 확보율을 재고, 50편은 오매칭이 없는지 직접 확인한다. 지금은 한 폴더 30편(29편 확인, 오매칭 확인 안 함)만 봤다.
3. **SMB 추출 동시성**: 동시성 1·2·3일 때 파일당 추출 시간을 재서 지금 값(해시 2, 추출 3)을 확정한다.
4. **설치**: schema 3 라이브러리는 0.2.10 이하 앱에서 열리지 않는다. 설치 전에 이전처럼 `app-backups/`에 앱과 DB 스냅샷을 남긴다.
