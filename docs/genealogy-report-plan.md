# 컬렉션 계보 리포트 자동화 계획 · 2026-10-25

프로젝트의 컬렉션 하나를 출발점으로, 연구 질문이 어떻게 출발해 발전하고 갈라졌으며 어떤 가지가 막히고 어떤 가지가 살아남았는지를 서술하는 계보(genealogy) 리포트를 앱 안에서 만든다. 리포트가 진행되며 새로 드러나는 중요한 논문은 아카이브·서고·OpenAlex에서 찾아 컬렉션에 넣고, 원문 확보부터 해당 절 재집필까지 자동으로 잇는다.

이 문서는 기술 검토와 구현 계획이다. M0–M5의 구현과 검증은 [구현 기록](genealogy-report.md)에 있다.

## 1. 배경

### 1.1 지금의 작업 흐름

1. 연구 질문을 검색창에 넣어 OpenAlex 결과를 보고, 중요한 논문을 seed로 지정한다.
2. seed에서 `관련 논문`, `공통 참고문헌`(과거), `후속 인용`(미래)으로 넓혀 질문별 문헌 집합을 만든다. 여기까지는 ResearchBunny 안에서 한다.
3. 문헌 PDF를 폴더로 모아 Claude에게 넘긴다. Claude는 `literature-genealogy` 스킬대로 종설은 전부, 원저는 서론 중심으로 읽고 문헌 카드를 쓴 뒤, 상세 목차를 세우고 장별로 계보 종설을 쓴다. 본문 인용은 `[@citekey]`, 인용 문헌은 별도 `.bib`.
4. pandoc으로 Vancouver형 번호 인용 CSL을 적용해 EPUB·PDF를 만든다.
5. 쓰는 도중 중요한 논문이 새로 드러나면 손으로 찾아 아카이브에 저장하고, PDF를 받아 다시 넘긴 뒤 리포트를 다시 만들게 한다. **이번에 없애려는 반복은 이 단계다.** 3–4단계도 앱 밖에서 따로 돌아가므로 함께 옮긴다.

목적은 배경 지식이 부족한 분야를 가장 빨리 개관하는 것이다. 그러므로 리포트의 기준은 "이 분야를 시작하려는 사람이 흐름을 이해하는 데 필요한 수준"이며 분량 제한은 없다. 실험 하나하나의 세부는 필요 없지만 그 실험이 전체 흐름에서 무엇을 바꾸었는지는 독자가 알 수 있어야 한다.

### 1.2 과거 산출물에서 확인한 형식

`~/Library/CloudStorage/GoogleDrive-…/My Drive/_RESEARCH_/_ScholarPen_/` 아래의 결과물을 확인했다.

| 주제 | 위치 | 카드 | bib | 본문 | 렌더 |
|---|---|---|---|---|---|
| 환각제 작용기전의 계보 2012–2026 | `disruption-plasticity-rewiring/resources/genealogy/` | 108 | 113항목 | 164 KB, 서론 + 7부 + 종합 | `build-pdf.sh`(pandoc + xelatex), EPUB |
| 동역학계에서 동역학적 망으로 | `dst-for-mood-disorder/resources/genealogy/dynamic_network_neuroscience/` | 101 | 37 KB | 142 KB | EPUB |
| 기분조절제의 계보 | `mood-stabilizer/resources/genealogy/` | 38 | 22 KB | 40 KB | — |

자동화가 그대로 따라야 할 형식은 다음과 같다.

- **카드**: `cards/NNN_citekey.md`. 유형 R(종설)/M(체계적 고찰·메타분석)/O(원저)/P(주변 문헌), 계보 위치(누구에게 응답하고 누가 이어받는가), 문제제기, 주장, 근거(수치는 원문 그대로), 해석·방법론 비판, 미해결, 자금·이해상충·학파, 계보상 의의, ⚠ 주의. 본문의 숫자는 카드에서만 가져온다.
- **본문**: YAML(`title`, `lang: ko`, `bibliography`, `csl`, `reference-section-title: 참고문헌`, `link-citations: true`), 첫 **요지** 단락, `#` 부 / `##` 장 / `###` 절. 각 절은 논지 문장으로 시작하고 "주장 → 반론 → 둘을 가르는 증거" 순서로 쓰며, 증거를 들 때 그 설계가 무엇을 배제하는지 적는다.
- **다장 원고**(`dst-for-mood-disorder/drafts/dynamics-to-network/`): `00_contents.md`(상세 목차)를 먼저 쓰고 `01_서론.md`부터 장별 파일을 차례로 채웠다.
- **렌더**: `pandoc -f markdown-smart`(한국어 안의 따옴표가 뒤집히지 않게), `--citeproc`, CSL `clinical-psychopharmacology-and-neuroscience.csl`(등장 순서 번호 `[1]`, NLM/Vancouver형 참고문헌).
- **검증**: 본문 인용 키 집합 = bib 키 집합(누락 0, 미인용 0, 중복 0), pandoc 렌더에서 해석되지 않는 키 0.

### 1.3 이 Mac의 도구 (2026-10-25 확인)

pandoc 3.11, typst(`/opt/homebrew/bin/typst`), Quarto 1.10.18, TinyTeX xelatex(**xeCJK 미설치**), Claude Code 2.1.296, Codex CLI 0.160.0, Noto Serif KR·Pretendard·AppleMyungjo 글꼴.

## 2. 목표와 범위

목표:

- 프로젝트의 **컬렉션 하나**에서 시작한다. 아카이브 전체를 쓰지 않는다.
- 상세 목차를 먼저 만들고 절 단위로 차례로 채운다.
- 본문은 `[@citekey]`, 인용 문헌은 별도 `.bib`. EPUB·PDF는 번호 인용(Vancouver형)으로 렌더한다.
- 진행 중 드러난 중요한 논문을 **아카이브 → 서고 → OpenAlex** 순으로 찾아 컬렉션에 넣고, 원문 확보 → 카드 → 영향받는 절 재집필까지 잇는다.
- 몇 시간 걸리는 작업이므로 단계마다 저장하고, 취소·한도 도달·앱 재시작 뒤 이어서 한다. 컬렉션이 바뀌면 바뀐 부분만 다시 쓴다.

비목표:

- seed 선정과 첫 탐색(1.1의 1–2단계)은 지금처럼 사용자가 한다. 계보의 질은 출발 문헌에 달려 있고, 그 선택이 이 작업에서 사람이 판단할 몫이다.
- 체계적 고찰의 완전성 주장, 그림·표의 시각 해석, 스캔 PDF OCR.
- ScholarPen 원고 편집을 대신하지 않는다. 리포트는 작업 문서이며, 작업 폴더를 ScholarPen 프로젝트 안에 둘 수 있게만 한다.

## 3. 결론: 기술적으로 가능한가

가능하다. 필요한 부품의 절반 이상이 이미 앱에 있고, 새로 만들 것은 읽기·쓰기 단계의 프롬프트와 이를 묶는 작업 관리자, 그리고 집필용 모델 연결이다.

| 단계 | 이미 있는 것 | 새로 만들 것 | 난이도 | 주요 위험 |
|---|---|---|---|---|
| 컬렉션 읽기 | `collections`·`collection_works`, 아카이브 상태 | 시작 시점 문헌 목록 고정 | 낮음 | — |
| 서지 보강 | `OpenAlex.lookup` 일괄 조회, `Work.references`(참고문헌 OpenAlex ID), PMID·PMCID | 누락분 일괄 보강 | 낮음 | OpenAlex 누락·오류 |
| 유형 판정(R/M/O/P) | `Work.type`(OpenAlex `review`), PubMed 검색 모듈 | PubMed 출판 유형 확인, 애매하면 초록으로 AI 판정 | 낮음 | 종설 표지 누락 |
| 원문 확보 | `PDF 원문 찾기` 작업(서고 연결 → OA → Chrome → Sci-Hub 미러), 서고 색인 | 계보 작업에서 같은 작업을 호출 | 낮음 | 확보 실패 → 초록만 |
| 본문 추출 | pdf.js 워커(500쪽·200만 자), `bodyWithoutReferences` | 절 나누기(서론·방법·논의), Europe PMC JATS 전문 | 중간 | 2단 조판 읽기 순서 |
| 문헌 카드 | `AIProvider.structured`(스키마 출력), 인용문 원문 일치 검증(`evaluate`) | 카드 스키마·프롬프트, 긴 종설 분할 처리 | 중간 | 입력량, 환각 |
| 공백 탐지·확장 | 공통 참고문헌·공통 후속 연구 계산, 후보·근거(`Evidence`) 저장, 서고 의미 검색 | 네 가지 신호, 점수, 채택·되돌리기 | 중간 | 주제 이탈 |
| 계보 분석·목차 | 인용 관계, 연도 | 가지 장부, 목차 생성·편집·승인 | 중간 | 모델 품질 |
| 집필 | — | 절 단위 집필, 키·숫자 검증, 누락 근거 요청 | 높음 | 문체·일관성 |
| bib | `exportBib`, 고유한 `works.citekey`, 가져온 bib 키 보존 | 인용 집합만 내보내기 | 낮음 | — |
| 렌더 | — | pandoc + CSL, PDF는 typst | 낮음 | 외부 도구 의존 |

위험이 큰 순서:

1. **집필 품질**은 모델이 정한다. 지금 쓰는 Codex 구독(gpt-6.1)으로 충분히 쓸 수 있고, 지금까지의 리포트를 쓴 Claude도 구독으로 쓸 수 있게 Claude 연결을 추가한다(D2). 새 설정의 기본값인 Ollama Cloud `gpt-oss:120b`는 집필용으로 권하지 않는다.
2. **PDF 본문 품질**: pdf.js는 2단 조판에서 읽기 순서가 섞일 수 있다. PMC에 있는 논문은 Europe PMC의 구조화된 전문(JATS XML)을 먼저 쓰고, 절을 찾지 못하면 그 사실을 카드에 남긴다.
3. **사용 한도와 시간**: 100편 규모면 호출 약 200회, 입력 약 250만–300만 토큰이다(10장). 구독 한도 창에 걸리면 단계 경계에서 멈추고 재개한다.
4. **신뢰할 수 없는 본문**: PDF 안의 문장이 지시처럼 작동하지 않도록 모든 AI 호출은 도구 없이 하고, 출력은 스키마·키·인용문 검증을 거친 뒤에만 반영한다(11장).

## 4. 설계 결정

### D1. 앱이 순서를 쥐는 단계 파이프라인 (추천)

| | A. Claude Code가 주도 (앱은 MCP 도구 제공) | **B. 앱이 주도하는 단계 파이프라인** | C. 앱이 headless Claude Code 에이전트를 띄움 |
|---|---|---|---|
| 시작 | Claude Code 세션에서 스킬 호출 | 컬렉션에서 버튼 | 컬렉션에서 버튼 |
| 진행 표시·재개 | 대화 맥락에 의존 | 문헌·카드·절 단위로 저장, 재시작 뒤 재개 | 세션 단위, 중간 상태가 불투명 |
| 한도 관리 | 세션 한도 | 호출 수·입력량 상한, 한도 도달 시 일시정지 | 대화 턴 상한 정도 |
| 모델 | Claude만 | Claude·Codex·Ollama를 단계별로 | Claude만 |
| 보안 | 쓰기 도구를 가진 에이전트가 신뢰할 수 없는 본문을 읽음 | 도구 없는 호출, 앱이 검증 뒤 반영 | A와 같음 |
| 유연성 | 높음 | 중간(명시적 신호로 보완) | 높음 |
| 구현량 | 작음 | 큼 | 중간 |

B를 택한다. 이유:

- 몇 시간짜리 작업은 단계·문헌·절 단위로 저장해야 진행을 보여 주고, 실패한 곳에서 이어서 할 수 있다. 앱의 탐색 실행(`Run`)과 원문 확보 작업이 이미 같은 방식(취소·재개·`paused_budget`·`interrupted`)으로 동작한다.
- 증분 갱신은 "어느 절이 어느 카드를 썼는가"를 앱이 알아야 가능하다.
- 기존 스킬도 사실상 단계 파이프라인이다(카드 → 축 → 집필 → 검증). 에이전트의 자율성이 필요한 지점은 "근거가 더 필요하다"는 판단 하나인데, 이는 카드와 절 출력의 명시적 필드(`foundations`, `missingSources`)로 받는다.
- 앱의 AI 호출은 이미 도구 없는 호출이다(Codex `sandbox: read-only`, 도구 금지 지시). 같은 원칙을 유지한다.

A의 MCP 다리는 버리지 않고 M6에서 "만든 리포트를 Claude Code와 대화로 고치기"용으로 붙인다. 같은 계보 엔진의 연산을 도구로 노출하는 것이므로 중복 구현이 아니다.

### D2. 집필 모델: Codex 구독과 Claude 구독, 단계별 모델

- 지금 쓰는 Codex 구독(gpt-6.1)은 그대로 집필 엔진 후보다.
- ScholarPen의 `src/bun/claude/client.ts`(Claude 구독 연결)를 옮겨 네 번째 공급자로 둔다(2026-10-25 구현, 아래 9장). 같은 Bun 환경이고, 2.1.273·2.1.296에서 검증된 방식이다: 설치된 공식 `claude` CLI, 앱 전용 `CLAUDE_CONFIG_DIR`, `auth login --claudeai`, `--safe-mode --print --tools "" --strict-mcp-config --no-session-persistence --max-turns 1`, 환경 변수 허용 목록, 한도·초과 사용 이벤트에서 중단, 유료 API 자동 전환 없음.
- 계보 리포트는 단계별로 모델을 고른다. 기본값 제안:

  | 단계 | 기본 | 이유 |
  |---|---|---|
  | 유형 판정·절 경계 보정·후보 관련성 판정 | 작은 모델(Ollama 또는 Claude Haiku급) | 짧고 많다 |
  | 문헌 카드 | 중간 모델(Claude Sonnet급 또는 Codex) | 정확한 추출, 호출 수가 많다 |
  | 가지 장부·목차·집필·검토 | 가장 좋은 모델(Codex gpt-6.1 또는 Claude Opus급) | 품질이 결과를 정한다 |

- 앱의 기존 원칙대로 한 공급자가 실패해도 다른 공급자로 자동 전환하지 않는다.
- 구조화 출력: Codex는 `outputSchema`를 쓴다. Claude CLI와 Ollama는 Ollama Cloud에 이미 쓰는 방식(스키마를 프롬프트에 넣고 zod로 검증)에 한 번의 수정 재요청을 더한다.
- 계보 작업은 대화용 설정(`aiMaxInputTokens`, Codex 실행당 3회 호출)과 별도의 상한을 쓴다: 호출당 입력 상한, 작업당 호출 상한, 한도 도달 시 `paused_budget`.

### D3. 파일이 내용, DB는 상태

- 계보 리포트마다 **작업 폴더**를 하나 둔다. 만들 때 위치를 고르고 기본은 라이브러리 안(`library/genealogies/<id>/`)이다. ScholarPen 프로젝트의 `resources/genealogy/<slug>/`를 고르면 과거 산출물과 같은 자리에 쌓인다.
- 폴더 구성은 과거 형식을 따른다.

  ```
  <작업 폴더>/
    cards/NNN_citekey.md        사람이 읽는 카드
    cards/NNN_citekey.json      기계용 카드(앱이 읽음)
    00_contents.md              상세 목차 (절 ID·배정 키를 주석으로 포함)
    01_서론.md … NN_종합.md      장별 본문
    부록A_가지_장부.md           가지별 출발·전환점·상태·근거
    <slug>.bib                  본문에서 인용한 문헌만
    <style>.csl
    build/<slug>.md · .epub · .pdf
    history/                    이전 판
  ```

- 추출한 본문 텍스트 캐시는 첨부 해시를 키로 라이브러리 안에만 두고 작업 폴더로 내보내지 않는다(크기·저작권).
- 앱이 쓴 파일의 해시를 기록한다. 사용자가 고친 파일은 덮어쓰지 않고, 새 판을 옆에 두고 알린다.

### D4. citekey

- 리포트의 키는 `works.citekey`를 그대로 쓴다. DB에서 고유하므로 `exportBib`의 키와 일치하고, 기존 `.bib`에서 가져온 문헌은 원래 키를 유지하므로 다른 원고와도 맞는다.
- 새로 만들어지는 키 형식(`성 + 연도 + 제목 첫 단어`, 예: `CarhartHarris2014The`)은 스킬의 소문자 규칙과 다르다. 키를 바꾸면 다른 원고의 인용이 깨지므로 기본값은 "그대로 두기"로 하고, 바꿀지 여부는 13장에서 결정한다.

### D5. 확장 정책

PRD P2-01은 "자동 확장은 후보까지만 수집하고 채택은 사용자에게 맡김"이었다. 이번 요청은 채택까지 자동화하는 것이므로 세 가지 방식을 둔다.

| 방식 | 동작 |
|---|---|
| 끄기 | 컬렉션 문헌만으로 쓴다. 공백 후보는 부록 목록으로만 남긴다. |
| 제안만 | 후보를 검토함에 쌓고, 사용자가 채택한 것만 반영한다. |
| **자동 채택(기본 제안)** | 예산 안에서 앱이 채택한다. 추가한 문헌마다 이유와 근거를 남기고, 한 번에 되돌릴 수 있다. |

- 찾는 순서: 컬렉션 → 프로젝트 아카이브 → 서고(모든 프로젝트에서 쓰는 로컬 PDF 라이브러리) → OpenAlex. 아카이브·서고에서 찾으면 내려받지 않고 컬렉션에 넣는다.
- 기본 예산(설정 가능): 한 차례 최대 15편, 최대 3차례, 처음 컬렉션 규모의 50%까지.
- 컬렉션에 넣으면 기존 `collectionMembers`처럼 아카이브(`screening: included`)에도 들어간다. 되돌리기는 컬렉션에서 빼고, 계보 작업이 아카이브에 처음 넣은 문헌이면 아카이브에서도 뺀다.

### D6. 렌더

- 본문 파일들을 하나의 `build/<slug>.md`로 합치고(YAML 포함) pandoc으로 렌더한다.
- EPUB: `pandoc -f markdown-smart --citeproc --csl … --toc --split-level=2 -o …epub` + 한국어 본문용 CSS.
- PDF: **typst 엔진을 기본**으로 한다(`--pdf-engine=typst`, 본문 Noto Serif KR). 설치되어 있고 TeX 패키지 문제가 없다. 과거의 xelatex 경로는 xeCJK가 설치된 경우에만 쓴다.
- CSL은 과거에 쓴 `clinical-psychopharmacology-and-neuroscience.csl`을 기본으로 넣고, 사용자가 다른 `.csl`을 고를 수 있게 한다.
- pandoc·typst를 찾지 못하면 Markdown + bib만 만들고 설치 안내를 보인다. 앱 번들 안의 대체 렌더러(citation-js CSL + HTML → EPUB)는 필요해지면 나중에 만든다.

## 5. 파이프라인

각 단계는 `Run`으로 기록하고(원문 확보 작업처럼 `run.genealogy`에 단계 정보를 둔다) 진행·취소·재개를 기존 작업 목록에서 다룬다.

### S0. 만들기

컬렉션 메뉴의 `계보 리포트 만들기`. 대화상자에서 정한다:

- 제목, 연구 질문(프로젝트 질문·최근 seed 질문으로 미리 채움)
- 독자(기본 "이 분야를 처음 시작하는 연구자", 예: "정신과 의사"로 바꿀 수 있음), 언어(기본 한국어)
- 확장 방식과 예산, 단계별 모델, 목차 승인 뒤 멈추기(기본 켬), CSL, 작업 폴더
- AI 공급자로 보내는 내용(문헌 본문의 해당 부분, 제목·초록, 연구 질문. 개인 노트는 보내지 않음) 안내

### S1. 문헌 확정과 서지 보강

1. 컬렉션 문헌을 계보 문헌 목록으로 고정한다(이후 컬렉션 변화는 S10에서 반영).
2. OpenAlex 일괄 조회로 `references`·유형·연도·PMID·PMCID가 없는 문헌을 채운다.
3. 유형 판정: PubMed 출판 유형(Review, Systematic Review, Meta-Analysis 등) → OpenAlex `type` → 둘 다 애매하면 제목·초록으로 작은 모델이 R/M/O/P를 고른다. 사용자가 문헌 표에서 고칠 수 있다.

### S2. 원문 확보

1. 서고에 같은 문헌이 있으면 연결한다(기존 동작).
2. 첨부가 없는 문헌은 기존 `PDF 원문 찾기` 작업을 `selected` 범위로 호출한다. 사용자가 설정한 경로(Chrome, Sci-Hub 미러 포함)를 그대로 따른다.
3. PMCID가 있는 문헌은 Europe PMC의 JATS 전문(`https://www.ebi.ac.uk/europepmc/webservices/rest/{PMCID}/fullTextXML`, PMC 공개 전문에 한함)을 받아 둔다. 절 구분이 명시되어 있어 PDF보다 정확하다.
4. 어느 것도 없으면 초록만으로 진행하고 문헌 표와 카드에 `초록만`이라고 표시한다.

### S3. 읽을 범위 자르기

스킬의 원칙을 유형별 규칙으로 옮긴다.

| 유형 | 읽는 범위 |
|---|---|
| R 종설·개념·역사·논평 | 참고문헌 앞까지 전부 |
| M 체계적 고찰·메타분석 | 초록 + 서론 + 논의 |
| O 원저 | 초록 + 서론 + 논의 첫 단락·결론 |
| P 주변 문헌 | 연구 질문 핵심어가 나오는 절 |

- JATS가 있으면 `<sec sec-type="intro|methods|results|discussion">`과 제목으로 자른다.
- PDF는 `bodyWithoutReferences`로 참고문헌을 떼고, 절 제목 정규식(Introduction/Background/Methods/Materials/Results/Discussion/Conclusion, 비영어 제목 포함)으로 경계를 찾는다. 경계 후보가 애매하면 제목 후보 목록과 앞뒤 몇 줄만 작은 모델에 보여 고르게 한다.
- 서론을 못 찾으면 본문 앞 25%를 서론으로 쓰고 카드에 "절 경계 추정"이라고 남긴다.
- 결과는 첨부 해시 기준으로 캐시한다.

### S4. 문헌 카드

문헌마다 한 번 호출한다(병렬 2–4개, 한도에 맞춰 조절). 출력은 다음 스키마를 따르고, 앱이 `cards/NNN_citekey.md`와 `.json`으로 쓴다.

```ts
interface GenealogyCard {
  key: string;                       // works.citekey
  type: "R" | "M" | "O" | "P";
  basis: "fulltext" | "sections" | "abstract";  // 실제로 읽은 범위
  position: string;                  // 누구에게 응답하고 누가 이어받는가
  problem: string;                   // 저자가 무엇을 문제로 보았나
  claims: string[];                  // 가설·주장·정의
  evidence: { text: string; quote: string }[];   // 수치는 원문 그대로, quote는 원문 그대로의 근거 문장
  critique: string;                  // 해석의 핵심, 방법론 비판
  unresolved: string[];
  interests: string;                 // 자금·이해상충·학파
  significance: string;              // 계보상 의의 1–2문장
  foundations: {                     // 이 글이 기대는 앞선 연구 (공백 탐지 신호)
    mention: string;                 // 원문 표기 그대로, 예: "Tononi and Edelman (1998)"
    role: "origin" | "support" | "refute" | "method" | "review";
    claim: string;
  }[];
  statusSignals: string[];           // "이 접근은 ~ 때문에 중단되었다" 같은 가지 상태 근거
  cautions: string[];
}
```

- `evidence[].quote`가 추출 본문의 부분 문자열이 아니면 그 근거를 버리고 `cautions`에 남긴다(지금 `AIProvider.evaluate`의 인용문 검증과 같은 방식).
- 호출당 입력 상한을 넘는 긴 종설은 최상위 절 단위로 나눠 부분 카드를 만든 뒤 하나로 합친다.
- 같은 저자 집단의 연작 종설은 스킬처럼 가장 완결된 한 편을 중심 카드로 두고 나머지는 고유 내용만 추린다(목차 단계에서 묶음 표시).

### S5. 공백 탐지와 확장

여기가 지금 손으로 하는 반복을 대신하는 부분이다. 네 가지 신호를 모은다.

| 신호 | 계산 | 무엇을 잡나 |
|---|---|---|
| a. 공통 참고문헌 | 계보 문헌들의 `references`를 세어 여러 편이 함께 인용하는데 목록에 없는 문헌. 종설과 서론에서의 인용에 가중치 | 출발점·고전·전환점 논문 |
| b. 카드 속 언급 | `foundations[].mention`을 **그 논문의 참고문헌 목록 안에서** 1저자 성·연도로 찾는다. 못 찾으면 OpenAlex 검색 | 본문이 기대는 원전 |
| c. 공통 후속 연구 | 계보 문헌 여러 편을 인용하는 최근 논문, 특히 종설·피인용 상위 | 지금 살아 있는 가지, 최신 정리 |
| d. 집필 중 요청 | S7의 `missingSources` | 쓰다가 드러난 빈자리 |

- b의 "참고문헌 목록 안에서 찾기"가 핵심이다. 저자·연도 문자열을 전 세계 문헌에서 찾으면 틀리기 쉽지만, 그 논문이 실제로 인용한 수십 편 안에서 찾으면 거의 정확하다.
- 점수(초안 가중치, 평가 뒤 조정): `0.35·a + 0.25·b + 0.15·c + 0.25·관련성`, d는 가산점. 관련성은 연구 질문과의 로컬 임베딩 유사도(Ollama `embeddinggemma`가 켜져 있을 때)와 작은 모델의 제목·초록 판정(역할: 기원/전환점/반박/최신 종설/무관 + 이유 한 줄)을 합친다.
- 채택한 후보는 D5의 순서(아카이브 → 서고 → OpenAlex)로 찾아 컬렉션에 넣고 S2–S4를 돈다. 각 추가에는 신호·점수·이유·요청한 절을 기록한다(`Evidence`와 같은 모양).
- 한 차례에서 기준을 넘는 새 후보가 몇 편 이하이거나 예산이 다하면 멈춘다.
- 실행 위치: a·b·c는 목차 전에 한 번(S5a), d는 집필 중에(S5b) 돈다.

### S6. 계보 분석과 상세 목차

1. **근거 묶음**을 만든다(결정적 계산): 연도별 문헌 표(키·유형·한 줄 주장), 계보 문헌 사이의 인용 관계(`references` ∩ 계보 문헌), 공통 인용·서지 결합으로 묶은 군집, 군집별 연도별 출판·후속 인용 수.
2. **가지 장부** 호출: 카드 요약 전체와 근거 묶음으로 가지(branch)를 정한다. 가지마다 출발 문헌, 핵심 주장, 전환점, 상태(`살아남음 / 막힘 / 합류 / 휴면 / 논쟁 중`), 상태 근거(카드의 `statusSignals`·반박 연구·후속 인용 추세), 막혔다면 그 이유(반박, 방법의 벽, 대체, 도구 부재)를 적는다. "막혔다·살아남았다"는 판단이 인상이 아니라 카드와 인용 추세에 근거하도록 하는 단계다.
3. **목차** 호출: 부·장·절과 절마다 논지 한 문장, 다룰 질문, 둘을 가르는 증거, 배정 키(주·부), 관련 가지, 예상 분량. 서론(문제가 어떻게 생겼나)과 종합(합의·열린 문제·새 가설)을 포함한다.
4. 출력은 사람이 읽는 `00_contents.md`로 쓰고, 기계용 정보는 절 제목 아래 주석으로 둔다.

   ```md
   ### 2.1 잡음 증가와 지형 유연화: 구별 가능한가
   <!-- rb:section id=2.1 keys=CarhartHarris2019,Moses2026,Irrmischer2026 branches=b2,b4 -->
   - 논지: …
   - 다룰 질문: …
   - 가를 증거: …
   ```

5. **승인 지점**(기본 켬): 목차를 앱에서 보이고 멈춘다. 사용자는 앱이나 외부 편집기에서 고친 뒤 `집필 시작`을 누른다. 앱은 주석을 다시 읽어 절 구조를 갱신한다. 목차는 고치기 싸고 본문은 다시 쓰기 비싸므로 이 지점에서 멈추는 것이 기본이다.

### S7. 집필

목차 순서대로 절마다 한 번 호출한다.

- 입력: 전체 목차, 이 절의 계획, 배정 키의 카드 전문, 같은 장 다른 문헌의 카드 요약, 가지 장부, 앞 절들의 요약(절마다 3문장), 집필 지침(6장), 인용 가능한 키 목록.
- 출력: 본문 Markdown, 이 절 요약 3문장, 사용한 키, `missingSources[]`(`{need, hint, kind: "primary" | "recent" | "counter"}`).
- 검사: 목록에 없는 키 → 한 번 수정 재요청 후에도 남으면 표시. 금지 인용 형식(번호, 평문 저자-연도, 각주, 본문 참고문헌 목록) → 재요청. 본문의 숫자가 카드에 없으면 표시(AI 추천의 `validateRecommendations`가 이유 문장의 숫자를 제목·초록과 대조하는 방식과 같다).
- `missingSources`는 S5b로 간다. 채택된 문헌의 카드가 생기면 **그 절만** 다시 쓴다. 한 실행에서 절당 재집필은 최대 2회.
- 장은 `NN_장제목.md`로 저장한다. 첫판은 순서대로 쓰고(앞 절 요약이 다음 절의 맥락), 장 단위 병렬은 목차에 장별 요약이 충분할 때만 켠다.

### S8. 검증

스킬의 체크리스트를 자동 검사로 옮긴다.

- 인용 키 집합 = bib 키 집합, 중복 키 0
- pandoc `--citeproc` 시험 렌더에서 해석되지 않는 키 0
- 본문 숫자 ↔ 카드 대조, 배타적·비교 주장("최초", "유일", "first", "only", "더 우월") 목록
- 계보 문헌이 모두 본문에 등장하는지(나오지 않은 문헌은 목록으로 보여 주고, 주변 문헌으로 배치할지 묻는다)
- 선택: 장마다 검토 호출 한 번으로 카드와 어긋나는 주장을 표시(자동으로 고치지 않음)

결과는 `검증` 탭에 항목별로 보이고, 통과하지 못한 항목이 있어도 렌더는 할 수 있다.

### S9. bib과 렌더

1. 본문에서 키를 뽑아 그 문헌만 `exportBib`으로 `<slug>.bib`에 쓴다.
2. 장 파일을 합쳐 YAML(`title`, `subtitle`, `date`, `lang: ko`, `bibliography`, `csl`, `reference-section-title: 참고문헌`, `link-citations: true`)을 붙인다.
3. pandoc으로 EPUB·PDF를 만든다(D6). 실패하면 pandoc 출력의 오류를 그대로 보인다.

### S10. 증분 갱신

- 컬렉션에 문헌이 추가·제거되거나 사용자가 `다시 읽기`를 누르면, 바뀐 카드만 다시 만든다.
- 절 ↔ 키 대응으로 영향받는 절을 찾는다. 새 문헌은 작은 호출로 들어갈 절을 고르고, 맞는 절이 없으면 "새 절 필요"로 표시한다.
- 다시 쓴 절은 이전 판을 `history/`에 남긴다. 사용자가 고친 파일은 덮어쓰지 않는다(D3).

## 6. 집필 지침 (프롬프트에 고정할 내용)

사용자 요구와 `literature-genealogy` 스킬에서 가져온다.

- 한국어 논증적 산문. 장·절은 논지 문장으로 시작하고, 문헌은 그 논지의 근거로 묶어 인용한다. 논문을 한 편씩 나열하지 않는다.
- 이 분야를 처음 시작하는 독자(설정한 독자)를 기준으로, 용어는 처음 나올 때 풀어 쓴다.
- 실험을 들 때는 세 가지만 쓴다: 그 실험이 흐름의 어떤 질문에 답하려 했는지, 설계·결과의 요점 한두 문장, 그 결과가 무엇을 배제하거나 바꾸었는지. 방법의 세부는 쓰지 않는다.
- "주장 → 반론 → 둘을 가르는 증거"의 순서를 기본으로 한다.
- 가지마다 상태를 분명히 한다: 막혔다면 왜 막혔는지, 살아남았다면 무엇이 살아남게 했는지, 과거 논쟁이 새 방법론의 언어로 되돌아오는지.
- 숫자는 카드에서만 가져온다. 누가 그 주장을 했는가(학파·내부자·업계 후원)가 의미 있으면 밝힌다.
- 인용은 `[@key]`, `[@a; @b]`, `[@key, p. 12]`, `@key 는 …`만 쓴다. 번호 인용, 평문 저자-연도, 각주 인용, 본문 끝 참고문헌 목록, 본문 속 URL·DOI는 쓰지 않는다.
- 인용 가능한 키 목록 밖의 문헌은 인용하지 않는다. 필요하면 `missingSources`로 요청한다.
- 분량 제한은 없다. 기준은 "흐름을 이해하는 데 필요한가"다.

## 8. 화면

- **들어가는 곳**: 컬렉션 오른쪽 클릭 메뉴와 컬렉션 화면 머리의 `계보 리포트`. 사이드바의 프로젝트 아래 `계보 리포트` 묶음에 만든 리포트가 보인다.
- **작업 화면**(목록 자리에 열림) 탭:
  - `진행`: 단계 표시(자료 확정 → 원문 → 카드 → 공백 점검 → 목차 → 집필 → 검증 → 렌더), 단계별 편수·호출 수·남은 예산, 일시정지·재개·취소.
  - `문헌`: 유형, 읽은 범위(전문/절/초록만), 카드 상태, 출처(컬렉션/아카이브/서고/OpenAlex). 행을 누르면 오른쪽 문헌 패널과 카드.
  - `추가`: 자동·제안된 문헌과 이유·신호·요청한 절, 채택/거절/되돌리기.
  - `목차`: `00_contents.md` 보기·편집, 가지 장부, `집필 시작`.
  - `본문`: 장별 미리보기. `[@key]`를 번호로 바꿔 보이고, 번호에 마우스를 올리면 문헌 정보, 누르면 오른쪽 패널에 그 문헌.
  - `검증·내보내기`: S8 결과, EPUB·PDF·Markdown+bib 만들기, 작업 폴더 열기.
- 기존 화면 규칙(한국어 이름, 도움말 툴팁, 사이드바·오른쪽 패널 구조)을 따른다.

- 계보 작업은 공급자별 동시 실행 수(Claude·Codex 2–4, Ollama 4)를 따로 정한다.

## 10. 규모와 시간 추정

종설 40편 + 원저 60편, 확장 30편을 가정한 대략값이다.

| 단계 | 호출 | 입력 토큰 | 출력 토큰 |
|---|---|---|---|
| 유형 판정·절 경계 | 30–60 | 0.05M | 적음 |
| 카드 (처음 100편) | 100 | 0.9M | 0.12M |
| 공백 판정 | 6–10 | 0.06M | 적음 |
| 카드 (추가 30편) | 30 | 0.3M | 0.04M |
| 가지 장부·목차 | 2–3 | 0.2M | 0.02M |
| 집필 (35절 안팎 + 재집필) | 40–50 | 0.7M | 0.12M |
| 검토(선택) | 10 | 0.5M | 0.03M |
| **합계** | **약 200** | **약 2.7M** | **약 0.35M** |

- 시간: 카드는 병렬 3개로 30–45분, 집필은 순서대로 1.5–2.5시간. 원문 내려받기를 빼고 3–4시간 안팎이다.
- 구독 등급에 따라 사용 한도 창에 걸릴 수 있다. 그때는 단계 경계에서 멈추고 한도가 풀린 뒤 이어서 한다.
- OpenAlex: 서지 보강·공통 후속 연구 조회가 수십 회 수준(필터 조회는 1 credit). 이름·연도 검색은 10 credit이므로 b 신호의 검색은 참고문헌 목록 안에서 못 찾은 경우에만 쓴다.

## 11. 보안·개인정보

- 문헌 본문은 신뢰할 수 없는 입력이다. 모든 AI 호출은 도구 없이 하고, 지시문은 시스템 프롬프트에만 둔다. 출력은 스키마 검증, 키 허용 목록, 인용문 원문 일치를 통과한 것만 반영한다.
- 본문 속 URL은 자동으로 열지 않는다. 문헌 해석은 DOI·OpenAlex ID를 통해서만 한다.
- Mac 밖으로 나가는 것: 선택한 AI 공급자에게 문헌 본문의 해당 부분, 제목·초록, 연구 질문. 개인 노트는 보내지 않는다. 만들기 대화상자에서 이를 알린다.
- 유료 API로 자동 전환하지 않는다. 키는 지금처럼 키체인에만 둔다.
- 추출 본문 캐시는 라이브러리 안에만 둔다. 카드는 요약과 짧은 근거 인용만 담는다.

## 12. 검증 계획

- 결정적 통합 테스트(가짜 공급자): 카드 스키마·인용문 검증, 긴 종설 분할·병합, 절 나누기(실제 논문에서 모은 제목 변형 표본), 공백 신호 a–d(합성 인용 그래프), 채택·되돌리기와 아카이브 상태, 절 재집필 무효화, 키 집합 검사, 사용자 수정 보호, 재시작 뒤 재개.
- pandoc 렌더 시험: pandoc·typst가 있으면 EPUB·PDF를 만들고 참고문헌 수 = 키 수를 확인한다. 없으면 건너뛰고 그렇다고 보고한다.
- 실제 앱 QA는 **QA 전용 라이브러리**와 작은 컬렉션(15편 안팎)으로 한다. 실제 라이브러리에 설치하거나 실험하지 않는다.
- 품질 비교: 과거 산출물 하나(예: 환각제 작용기전 108편)의 문헌 목록으로 QA 컬렉션을 만들어 돌리고, 목차·가지 구분·막힌 가지 판정을 기존 리포트와 나란히 읽어 본다.
