# 프로젝트 관리

- 프로젝트 목록은 최근에 연 순서로 보인다. 프로젝트를 열면 맨 위로 올라가고, 앱을 다시 열면 맨 위 프로젝트로 시작한다. 이전에는 앱을 열 때마다 가장 먼저 만든 프로젝트로 시작했다.
- 연 시각은 `project_opens` 표에 둔다. `projects`에 열을 더하지 않아 라이브러리 스키마는 3 그대로이고, 이전 앱도 프로젝트를 읽고 만들 수 있다. 이 기능 전에 연 기록은 없으므로, 아직 열지 않은 프로젝트는 만든 시각을 연 시각으로 본다.
- 프로젝트 전환 목록 아래 `프로젝트 관리`가 설정의 `프로젝트` 항목을 연다. 여기서 이름을 바꾸고(Enter 저장, Escape 취소) 프로젝트를 삭제한다. 연구 질문은 바뀌지 않는다.
- 삭제는 확인 창에서 지워지는 것을 센다: 문헌 상태·메모·태그, 컬렉션, 탐색·가져오기·원문 확보 기록, AI 대화, 초기 관심 문헌, 자동 분류 주제, 저장된 화면, 실행 취소 기록. 복원할 수 없다.
- PDF 파일은 서고 PDF를 포함해 지우지 않는다. 다른 프로젝트, 서고, 남은 탐색 기록이 쓰는 문헌은 기록을 유지하고, 아무 데도 쓰이지 않는 문헌만 라이브러리에서 빠진다. 휴지통 영구 삭제와 같은 규칙(`purgeUnreferencedWorks`)을 쓴다.
- 탐색·가져오기·자동 분류·AI 대화 작업이 진행 중이면 삭제를 거절한다. 마지막 남은 프로젝트는 삭제할 수 없다.
- 열려 있는 프로젝트를 삭제하면 먼저 다음으로 최근에 연 프로젝트로 전환한 뒤 삭제한다. 그래서 삭제 뒤에는 지운 프로젝트를 읽거나 저장하는 요청이 생기지 않는다. 삭제가 거절되면 원래 프로젝트로 돌아온다.

## 검증

- 타입 검사·린트 통과. 통합 테스트에 `projects.test.ts` 추가: 열람 순서와 재시작 후 유지, 같은 프로젝트를 다시 열 때 쓰기 없음, 이름 변경 시 연구 질문 유지, 삭제 범위(프로젝트 표·채팅 머리·환경설정 키·병합 기록), 공유·서고·다른 프로젝트 초기 관심 문헌 유지, PDF 파일 유지, 작업 중·마지막 프로젝트·없는 프로젝트 거절.
- 실제 렌더러를 별도 QA 라이브러리에 연결해 확인했다(`.qa/project-management/`): 전환 후 목록 순서, 설정의 프로젝트 항목, 이름 변경 후 사이드바·경로 갱신, Escape 취소, 열린 프로젝트 삭제 후 전환과 안내, 작업 중 거절 시 원래 프로젝트 복귀, 프로젝트 하나일 때 삭제 비활성, 긴 이름 줄바꿈, 밝은·어두운 테마. 서버 로그와 콘솔에 의도한 거절 외 오류 없음.
