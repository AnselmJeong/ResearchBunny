# ResearchBunny 다운로드·첨부 감사

최초 확인: 2026-10-02 06:32:35 KST. 설치 후 확인: 2026-10-02T07:05:17.305388+09:00. 대상: 스크린샷에 표시된 `/Volumes/Aquatope/Downloads`의 PDF **43개**. 디버깅 중 생성한 QA 파일과 관계없는 책은 제외했다.

## 설치 후 확인 결과

- `/Applications/ResearchBunny.app`을 **0.2.5**로 업데이트했다. 실제 다운로드 폴더를 기억하도록 설정한 뒤, 설치한 앱의 자동 복구 모니터가 기존 실행 기록과 파일을 대조해 본문 **8편**을 기존 항목에 첨부했다. 논문별 수동 첨부는 하지 않았다.
- 스크린샷 파일 **41개**가 DB 첨부·실제 저장소 복사본과 같은 SHA-256을 가진다. 이 중 9개 파일은 자동 복구한 8편의 본문이다. Brown 논문의 두 파일은 바이트가 같아 하나의 첨부를 공유한다.
- 보충자료 `mmc1.pdf`와 정오표 `researchbunny-f14886f9-3764-4921-9de1-74fe30f136a4.pdf`는 본문으로 대체하지 않았다. 다운로드 폴더의 원본은 유지했다.
- 실제 앱의 전체 첨부는 **57개 → 65개**다. 65개 모두 파일 존재와 SHA-256이 일치한다. 다운로드 원본 43개의 바이트도 최초 감사와 같다.
- 문헌·프로젝트·아카이브 상태·소주제 분류·컬렉션 테이블을 업데이트 전 DB 백업과 대조했다. 서지정보, 분류, 노트, 읽기 상태에 변화가 없다.
- 실제 앱 화면과 DB의 기존 111편 작업 결과는 **새 PDF 39편 · 기존 26편 · 제외 1편 · 실패 45편 · 실패 항목 재시도 가능**로 갱신됐다. 자동 복구 8편 각각에 `다운로드 파일 자동 복구·검증·첨부 완료`와 원본 경로가 기록됐다. 나머지 45편은 여전히 실패 상태이며, 이번 확인이 모든 문헌의 원문 확보를 뜻하지는 않는다.

## 왜 다운로드는 됐는데 첨부되지 않았나

1. **잘못된 폴더를 조용히 감시하는 경로가 있었다.** Chrome 환경 설정 파일에 접근이 거부돼도 오류를 무시하고 홈의 Downloads를 감시했다. 실제 저장 위치는 `/Volumes/Aquatope/Downloads`였다. 실제 Chrome으로 공개 PDF를 내려받는 재현에서 다운로드 완료와 파일 저장을 확인했지만, 수집기는 홈 폴더에서 파일을 찾다가 `CHROME_DOWNLOAD`로 끝났다. 이제 폴더 감지 실패를 명시하고 선택한 실제 폴더를 기억한다.
2. **시간 초과 뒤 도착한 파일을 다시 처리하지 않았다.** 각 문헌 시도의 시작 시점에 있던 파일을 제외하는 방식이었다. 이전 문헌의 PDF가 뒤늦게 도착하면 다음 문헌의 기존 파일 목록에 포함돼 수집에서 빠졌다. 완료된 작업을 대조하는 경로도 없었다. 이제 시작 전·문헌 처리 후 기존 다운로드를 확인하고, 완료된 작업도 앱 실행 중 5초마다 확인한다. 재시작 후에도 저장한 폴더와 작업 대상으로 복구한다.
3. **일시적인 탭 제어 오류가 후속 문헌까지 차단했다.** 최초 `CHROME_CONTROL` 뒤 39편이 같은 오류로 기록됐다. 일시적 탭 종료·시간 초과도 작업 전체의 Chrome 사용을 막았기 때문이다. 0.2.4부터는 해당 문헌에 한정하며, 전역 중단은 권한·JavaScript 허용·폴더 접근 오류에만 적용한다.

이전 작업은 실제 감시 폴더와 Apple Events 오류 번호를 저장하지 않았다. 따라서 초기 실패 각각이 어떤 오류 번호·폴더 상태였는지는 확정할 수 없다. 위 원인은 코드 경로와 현재 재현으로 확인했다. 누락 11개 파일의 해시는 최초 감사에서 DB와 관리 저장소 모두에 없었으므로, 이미 저장한 첨부를 잃은 문제가 아니라 저장소에 넣기 전의 수집 문제였다.

`researchbunny-UUID.pdf`는 브라우저 다운로드를 추적하기 위한 고유 이름이다. 출판사 파일명은 유지될 수 있다. 앱의 관리 저장소는 `library/attachments/<SHA-256>.pdf`이므로 파일명 접두어만으로 첨부 완료를 판단할 수 없다.

## 최초 감사와 자동 복구 범위

- 최초에는 32개 파일이 연결됐고 11개가 미연결이었다. 미연결은 본문 8편, 같은 본문의 중복 파일 1개, 보충자료 1개, 정오표 1개였다.
- 최초 등록 첨부 57개 전체에도 누락·손상·해시 불일치는 없었다.
- 안정된 PDF의 DOI와 제목이 기존 문헌 하나에 강하게 일치할 때만 자동 첨부한다. 참고문헌에만 있는 DOI, 애매한 제목, 보충자료와 정오표는 본문으로 처리하지 않는다. 취소·건너뛴 항목과 아카이브에서 제거된 문헌도 자동 복구하지 않는다.
